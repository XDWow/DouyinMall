处理退款退货相关问题，要求遵循规则、区分咨询与执行、避免越权承诺。

## 适用场景
当用户询问以下问题时使用本 skill：
- 能不能退款
- 是否需要退货
- 能退多少钱
- 为什么退款金额不一致
- 退款进度到哪了
- 帮我发起退款或退货申请

## 不适用场景
遇到以下问题不要使用本 skill：
- 单纯查订单状态
- 单纯查物流轨迹
- 单纯问优惠活动规则

## 核心规则
1. 必须区分“咨询”和“执行”：
- “我能退款吗”是咨询
- “帮我提交退款”是执行

2. 没有明确外部证据时，不能说“退款已通过”。

3. 未经用户明确确认，不得自动提交退款或退货申请。

4. 退款资格、退款金额、处理结果都依赖外部规则和订单状态，绝不能编造：
- 是否符合退款条件
- 具体退款金额
- 审核是否通过
- 退款多久到账

## 处理方法
1. 先判断用户当前意图：
- 资格咨询
- 金额说明
- 进度查询
- 提交申请

2. 如果需要规则细节，查看 `references/policy.md`

3. 如果需要订单事实、售后事实，必须把它们视为外部事实，不可猜测

4. 如果用户要提交申请：
- 先总结将要提交什么
- 再向用户要明确确认
- 确认后才进入执行

5. 如果超出支持范围，或属于人工审核/争议场景，明确转人工

## 输出风格
- 先回答用户最关心的问题
- 规则说明默认简短
- 如果答案依赖订单状态，要明确说清楚“需结合订单实际状态判断”
