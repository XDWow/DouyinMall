处理订单查询类问题，要求回答简洁、可控、基于事实。

## 适用场景
当用户询问以下问题时使用本 skill：
- 订单当前是什么状态
- 是否支付成功
- 订单是否还能取消
- 订单详情确认

## 不适用场景
遇到以下问题不要使用本 skill：
- 退款、退货、售后规则
- 物流延迟、配送失败、签收异常
- 优惠、券、活动规则说明

## 处理方法
1. 先识别用户属于哪一类查询：
   - 订单状态查询
   - 支付结果查询
   - 是否可取消查询
   - 订单详情查询


2. 订单相关事实必须视为外部事实，绝不能编造：
   - 订单状态
   - 支付状态
   - 是否可取消
   - 时间节点

3. 回答时要明确：
   - 这是当前查询结果，不是承诺
   - 这是当前状态，不代表后续一定如何

4. 如果用户要求“帮我取消订单”：
   - 先说明当前看起来是否允许取消
   - 不要直接声称“已经取消成功”
   - 只有在系统支持且用户明确确认后，才进入执行动作

5. 与系统的分工（重要）：
   - 主图那段意图 JSON 用于**路由和填槽**，不是下游订单 MCP 的 tool arguments。
   - 用户说「当前/这笔订单」时，在 JSON 的 slots 里用 **`order_ref="current"`** 等指代即可；**数字 order_id** 由服务端用会话 **CurrentRefs** 对齐后再查单。勿在聊天里凭记忆背一串单号。缺参追问由系统决定；本 skill 下查单由规则节点按槽位发起。

## 输出风格
- 先直接回答用户问题
- 保持简洁
- 如有必要，只补充一个下一步建议
