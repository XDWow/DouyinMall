# 主图工作流

当前实现以 [builder.go](./builder.go) 为准。这里不再描述旧版缓存前置节点、旧子图桥接节点或已删除的历史路径。

## 固定主图

当前主图固定为：

`AccessGuardNode -> SessionLoadNode -> UnderstandingNode -> RouteNode -> 子图 -> FinalizeNode`

其中：

1. `AccessGuardNode`
   做准入校验。若请求直接被拦截，会短路到 `FinalizeNode`。
2. `SessionLoadNode`
   加载或创建会话，把跨轮上下文装进 `Session`。
3. `UnderstandingNode`
   统一做 `intent + rewritten_query + slots`。
4. `RouteNode`
   只按 intent 分发到业务子图。
5. `子图`
   负责真正的业务处理。
6. `FinalizeNode`
   汇总最终结果、补 trace、落缓存/落会话。

## 状态边界

- 全图只有一份共享 `State`
- `Session` 只存跨轮可复用信息
- `UnderstandingNode` 把主图理解结果回写到：
  - `state.Intent`
  - `state.RewrittenQuery`
  - `state.Session.Slots`

## 当前子图

### 确定性子图
- `AddToCartGraph`
- `AftersalesApplyGraph`

特点：
- 直接消费 `session.Slots`
- 缺参走 interrupt/resume
- 参数齐全后直接构造 `tool_calls`
- 统一交给 `ToolsNode`

### agent 子图
- `ProductServiceGraph`
- `OrderServiceGraph`
- `PromotionServiceGraph`
- `AftersalesPolicyGraph`

特点：
- 读型、说明型、歧义型问题
- 由子图内 Agent 决定直接回答、调工具或 clarification
- `PromotionServiceGraph`、`AftersalesPolicyGraph` 先 RAG，再进 Agent

### 兜底子图
- `UnknownGraph`

## 中断恢复

- 缺参和确认都在业务子图内部中断
- 使用 checkpoint + interrupt/resume
- 用户补参后直接恢复到原中断节点
- 不重新跑 `UnderstandingNode` 和 `RouteNode`
