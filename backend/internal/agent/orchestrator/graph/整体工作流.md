# Main Workflow

当前实现以 [builder.go](D:/workspace/go/DouyinMall/backend/internal/agent/orchestrator/graph/builder.go) 为准。主图固定为：

`AccessGuardNode -> SessionLoadNode -> UnderstandingNode -> RouteNode -> Subgraph -> FinalizeNode`

主图不直接做业务，不在全局缓存层提前短路。它只负责准入、会话、理解、路由和最终收口。

## Steps

1. `AccessGuardNode`
   做准入和基础校验。失败时直接短路到最终响应。
2. `SessionLoadNode`
   加载或创建会话，把跨轮上下文放进 `Session`。
3. `UnderstandingNode`
   统一产出 `intent`、`rewritten_query` 和 `slots`。
4. `RouteNode`
   只按 intent 分发到业务子图。
5. `Subgraph`
   执行业务逻辑。读型子图内部可以查缓存、RAG、调用 ADK Agent；写型子图走确定性参数和工具提交。
6. `FinalizeNode`
   汇总回复、trace、工具执行记录、缓存写回和会话结果。

## State Boundary

- 全图只有一份共享 `domain.State`。
- `Session` 只保存跨轮可复用信息，如当前商品、当前订单、候选列表和 slots。
- `UnderstandingNode` 回写：
  - `state.Intent`
  - `state.RewrittenQuery`
  - `state.Session.Slots`

## Current Subgraphs

### Deterministic Writes

- `AddToCartGraph`
- `AftersalesApplyGraph`

这些子图直接消费 slots，缺参时 interrupt，确认后构造受控工具调用。

### Read Agents

- `ProductServiceGraph`
- `OrderServiceGraph`
- `PromotionServiceGraph`
- `AftersalesPolicyGraph`

这些子图统一使用 `subgraph/readflow`。缓存命中直接收口；未命中再进入自己的读能力。外层仍是 Eino Workflow，内层 agent loop 使用 Eino ADK `ChatModelAgent`。

### Fallback

- `UnknownGraph`

## Interrupt And Resume

- 缺参和确认都在子图内部中断。
- 通过 checkpoint + interrupt/resume 恢复。
- 恢复后回到原中断点，不重新跑 `UnderstandingNode` 和 `RouteNode`。
