# 子图（Eino Subgraph）

**业务工作流落在哪、主图节点名对照**：见同目录 [README.md](./README.md)。

## 为何拆子图

把**一段完整业务**收进独立 `compose.Graph`，主图用 `AddGraphNode` 只看到一个入口；进出仍通过主图共享的 `*orchestratorstate.State`，经 `Prepare*Input` / `Apply*Result` Lambda 对齐字段。

## 子图之间不必同构

- **没有**规定所有子图必须「先 L1 → 再同一套节点顺序」。
- 各子图自行决定：要不要 L1、要不要 RAG、是否用 **`shared.SubgraphAgent`**（白名单工具 + 模型多轮）、是否只用规则拼 `ToolCallPlan`、skill 正文何时进提示词等。
- **复用** `SubgraphAgent`、`ToolExecNode`、`ResolveSemanticCachePolicy`、`RequiredMissingSlots` 等公共能力即可；**不共享**一条固定业务流程模板。

## 与主图、Finalize 的边界

- **主图**：路由到对应子图；不在主图里做业务推理。
- **子图**：产出 `FinalAnswer`、工具消息、检索文档等写入 `State`。
- **FinalizeNode**：面向用户流式透传、汇总完整回复、落库与缓存；**不调用模型**。

## 单节点是否一定要包子图

一步且无组合价值时可用主图 Lambda；当前订单/库存等仍用子图是为了模块边界与后续扩展。
